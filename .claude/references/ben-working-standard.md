# กติกาทำงานของเบน — ใช้ก่อนงานผลิตชุดใหม่

คำสั่งผู้ใช้ 4 พฤศจิกายน 2026 แทนกติกาเก่าที่ขัดกัน ชื่อช่องปัจจุบัน **บ่าวเบน อยากเป็นไทบ้าน** ใช้หน้าแผน Notion เดิมเป็นข้อมูลกลาง ไม่อ้างว่าทุกแชตซิงก์หรือทำงานเบื้องหลังเอง

## ก่อนผลิต

- งานคลิปชุดใหม่ต้องถามความยาวและพล็อต/อารมณ์เรื่อง ถ้าเบนตอบแล้วในงานเดียวกันให้ใช้คำตอบ ไม่ถามซ้ำ ไม่ใช้ความยาวร่างเก่าแทนความต้องการใหม่
- งานใหญ่ส่งตัวอย่างที่ตรวจได้ก่อน: พล็อตย่อ บทพูดเปิด/ปิด ภาพ 2–3 เฟรมที่เห็นฟอนต์ สี ตำแหน่งข้อความ และภาพจริง ถ้าจำเป็นค่อยทำตัวอย่างเคลื่อนไหว 10–20 วินาที
- รอเบนตรวจตัวอย่างก่อนเรนเดอร์เต็ม สังเคราะห์เสียงยาว หรือทำทุก EP รวมคำแก้ครั้งเดียวในรายการเดียว แล้วค่อยผลิต คำสั่งทั่วไปให้ทำต่อจนเสร็จไม่ข้ามขั้นตัวอย่างที่เบนกำหนดนี้ งานอ่าน/จัดไฟล์/แก้เฉพาะจุดที่สั่งแล้วทำต่อได้
- ทุกคลิปมีฮุกที่อิงเรื่องจริง เรื่องหลักที่มีจุดจบ และคำชวนติดตามที่บอกว่าจะได้ดูอะไรต่อ ทำเป็น EP ได้ แต่ไม่ยืดหรือกั๊กสาระเพื่อบังคับติดตาม ไม่รับรองยอดวิวหรือผู้ติดตาม

## ประหยัดโทเค็นและเวลา

อ่านข้อมูลเฉพาะงาน ค้นก่อนเปิดเอกสารยาว เก็บผลใหญ่เป็นไฟล์แล้วส่งกลับเฉพาะข้อค้นพบ/รหัส/ลิงก์ ใช้ metadata, pagination และช่วงข้อมูลที่จำเป็น เปิดข้อมูลฉบับเต็มเมื่อต้องยืนยันข้อเท็จจริงเท่านั้น

ใช้ทะเบียนฟุตเทจ แฮช ภาพตรวจ เวลา ASR สคริปต์ ฟอนต์ และคำสั่งที่เคยผ่านแล้วซ้ำ ตรวจว่าข้อมูลยังตรงไฟล์ก่อนใช้ ไม่ดาวน์โหลด/ติดตั้ง/ถอดเสียง/เรนเดอร์ซ้ำเพียงเพราะเปลี่ยนสกิล เก็บ cache ที่พื้นที่เขียนได้ สร้าง proxy สำหรับตัวอย่าง แยกงาน CPU หนักเมื่อเครื่องมีทรัพยากรน้อย

ค้นสกิล/ปลั๊กอินเฉพาะปัญหาที่ของเดิมแก้ไม่ได้ เปรียบเทียบประโยชน์กับค่าใช้จ่ายและเวลาติดตั้ง ไม่ติดตั้งทั้งคลัง ไม่อ้างตัวเลขลดโทเค็นหากไม่มี usage จริง ถ้าไม่มีข้อมูล usage ให้วัดจำนวนรอบอ่าน เรียกเครื่องมือ เรนเดอร์ และเวลาที่ใช้แทน โดยไม่เรียกสิ่งเหล่านี้ว่าโทเค็น

## โครงการที่แก้ต่อและใช้ซ้ำได้

ทุกไฟล์ที่ผลิตต้องมีต้นฉบับและวิธีแก้ต่อจริง ส่งโครงการที่เก็บ timeline/settings/text เป็น JSON, ภาพหรือวิดีโอสะอาดก่อนเผาข้อความ, เสียงพากย์/เพลง/SFX แยกเป็น stem ตามที่ใช้, ซับแยก และคำสั่งหรือสคริปต์ที่สร้างผลเดิมได้ บันทึกรหัสสินทรัพย์ แหล่งไฟล์ และ SHA-256 พร้อม cache รายช็อต เก็บต้นฉบับไม่ทับ และระบุไฟล์ที่ยังขาดตรง ๆ ไม่เรียก MP4 อย่างเดียวว่าโครงการแก้ไขได้

ก่อนสร้างใหม่ให้ค้นทะเบียนและไฟล์เดิมก่อน ใช้ภาพ เสียง ฟอนต์ บท ซับ คำสั่ง และ cache ที่ยังตรง hash/ค่าตั้งเดิมซ้ำ แก้เฉพาะช็อตหรือเลเยอร์ที่กระทบ ไม่ถอดเสียง ดาวน์โหลด สร้างภาพ หรือเรนเดอร์ทุกอย่างใหม่ถ้ายังใช้ผลเดิมได้ การเปลี่ยนความยาวอาจต้องปรับภาพ เสียง และซับใหม่ รายงานการใช้ซ้ำ/งานที่รันจริง ไม่อ้างเปอร์เซ็นต์ลดโทเค็นเมื่อไม่มี usage จริง

ใช้ [โครงการแก้ไขได้และ cache รายช็อต](editable-projects.md) สำหรับโครงสร้างไฟล์ วิธีรันซ้ำ และข้อจำกัด: โครงการนี้ไม่ใช่ native CapCut ข้อความที่เผาในภาพแก้เป็นเลเยอร์ไม่ได้ และ export 1080 ไม่กู้รายละเอียดที่ต้นฉบับเสียไป

## เสียงและส่งมอบ

ส่งบทพากย์อ่านเองที่ไม่มีคำสั่งตัดต่อปน และตารางภาพ/เวลาแยกกัน เสียงเบนอัดเองเป็นทางเลือกหลัก เสียงโคลนใช้เป็นเสียงนำทางได้เมื่ออยู่ในขอบเขตที่เบนเลือก ไม่ถือว่าเหมือนหรือผ่านตรวจเพียงเพราะ ASR อ่านได้

เก็บภาพสะอาดไม่มีเสียงพากย์ (picture-only), เสียงพากย์แยก, เพลงแยก และ MP4 สำหรับดูร่าง เพื่อแทนเสียงเบนโดยไม่สร้างภาพใหม่ หากความยาวเสียงเปลี่ยนต้องปรับจังหวะภาพและซับจากเวลาจริง อาจต้องเรนเดอร์ใหม่ ไม่รับรองการแทนเสียงแบบไม่แก้อะไรทุกกรณี SRT บน CapCut iPhone ให้ยึดข้อจำกัดในคู่มือเดิม

## ส่งมอบไฟล์ให้หาเจอและตรวจย้อนกลับได้

- ใช้ file ID และลิงก์หลักที่คงที่หนึ่งชุดต่อฉบับส่งมอบ วาง final render ที่ `05_ไฟล์พร้อมเผยแพร่` ของโครงการที่ตรวจ ID แล้ว แยกต้นฉบับ โครงการแก้ไขได้ และ cache ตามหน้าที่ ไม่วาง final ใต้ `02_ฟุตเทจต้นฉบับ`
- ก่อนบอกว่าส่งแล้ว อ่านกลับ file ID, ชื่อ, MIME type, จำนวน bytes และ parent ID ของไฟล์จริง ตรวจรายการในโฟลเดอร์ปลายทางว่ามี ID เดียวกัน และเปิดลิงก์ตรวจ breadcrumb/เส้นทางที่ผู้ใช้เห็น ถ้าเปิดมุมมองนั้นไม่ได้ให้บอกว่ายังไม่ตรวจ ไม่เดาจากชื่อโฟลเดอร์หรือผล upload อย่างเดียว
- หลังยืนยันไฟล์และปลายทางสำเร็จแล้วจึงอัปเดต delivery index และ Notion ให้ชี้ file ID/ลิงก์เดียวกัน การตั้งชื่อโฟลเดอร์ว่าพร้อมเผยแพร่ไม่ใช่หลักฐานว่าตรวจผ่านหรือเผยแพร่แล้ว
- แยกสถานะ `rendered`, `technical-QC`, `editorial-reviewed` และ `published` ตามหลักฐานจริง ระบุผู้ตรวจ/ขอบเขตที่ตรวจ ไม่ตีความว่าการส่งไฟล์คือเบนอนุมัติหรือโพสต์แล้ว และไม่สร้างด่านขออนุมัติใหม่จากเช็กลิสต์นี้ ใช้ขอบเขตและคำอนุมัติที่มีอยู่
- หลังส่งแล้วไม่เปลี่ยนชื่อหรือย้ายไฟล์เพียงเพื่อให้หาเจอง่ายขึ้น ส่งลิงก์ตรงกับเส้นทางที่ตรวจแล้วแทน หากต้องแก้งานให้ออกเวอร์ชันชัดเจน บันทึก file ID/ลิงก์ของฉบับใหม่และฉบับที่แทนที่ รายละเอียดอยู่ใน [ขั้นส่งมอบโครงการ](editable-projects.md#ตรวจปลายทางก่อนส่งลิงก์สุดท้าย)

## บันทึกและพัฒนา

หลังจบแต่ละงานหรือก่อนเปลี่ยนแชต บันทึกสิ่งที่ทำจริง ตำแหน่งไฟล์/เวอร์ชัน เครื่องมือ วิธีที่ผ่าน ปัญหา วิธีแก้ และคำแก้ของเบนลง Notion เดิม แยก “รู้จัก/อ่านเอกสารแล้ว”, “ทดลองผ่าน”, “ใช้กับงานจริงแล้ว” อย่าเปลี่ยนทุกการค้นพบให้เป็นสกิลติดตั้ง

ศึกษาผู้สร้างจากแหล่งที่เปิดได้ บันทึกแหล่ง วิธีที่นำมาปรับใช้ และผลทดลองของเรา ใช้หลักเล่าเรื่องและการทำงาน ไม่คัดบท ภาพ เพลง หรือประวัติคนอื่นมาเป็นของเบน การปรับคู่มือ/ตัวอย่างไม่ใช่การฝึกน้ำหนักโมเดล และไม่มีการศึกษาหรือบันทึกเบื้องหลังเองเมื่อไม่ได้รันงาน

อ้างอิง [แนวทางที่ศึกษา](creator-and-efficiency-notes.md) และ [ทะเบียนความสามารถ](capability-register.md)



## ทำงานต่อจากแชต — 5 พฤศจิกายน 2026

ใช้ [วิธีทำงานจากแชต](chat-execution.md) ร่วมกับทุกสกิล เมื่อผู้ใช้สั่งงานแล้วทำส่วนที่ได้รับอนุญาตจนเสร็จ ไม่หยุดเพื่อให้สั่งซ้ำ ตรวจทางเข้าถึงข้อมูลก่อนขอให้แนบใหม่ การแกะคลิปเป็นงานวิเคราะห์ ไม่ใช่การผลิตชุดใหม่ที่ต้องถามพล็อต/ความยาวหรือรอตัวอย่าง ข้อจำกัดบัญชีและเครื่องมือต้องรายงานตามจริง

## เพิ่มฝีมือจากคลิปอ้างอิง — คำแก้ 5 พฤศจิกายน 2026

ผู้ใช้ต้องการให้นำวิธีคิดและทักษะจากคลิปมาเพิ่มฝีมือการตัดต่อของงานเรา ไม่ใช่เพิ่มแค่ความสามารถเปิดลิงก์/วิเคราะห์ ใช้ [กระบวนการตัดต่อเล่าเรื่อง](story-driven-editing.md) เชื่อมคัดช็อต บท timeline ภาพ เสียง และการตรวจงาน เก็บเหตุผลตัดและคำแก้เพื่อใช้รอบถัดไป ไม่อ้างว่าทำได้ดีกว่าต้นทางหรือคลิปจริงดีขึ้นแล้วโดยยังไม่มีผลตรวจ
