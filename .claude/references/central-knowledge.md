# ข้อมูลกลางทักษะและวิธีเริ่มงานทุกแชต

คำสั่งเบนวันที่ 5 พฤศจิกายน 2026: รวบรวมข้อมูล ทักษะ สกิลและความสามารถให้ใช้ต่อข้ามแชตได้ และปรับใช้กับงานของเรา

## จุดอ้างอิงหลัก

- [หน้าแผนหลัก — บ่าวเบน อยากเป็นไทบ้าน](https://app.notion.com/p/40b52d4a2f43818d8e8ccf778995100f) ส่วน **7.8 ข้อมูลกลางทักษะและบทเรียน** เป็นดัชนีความรู้และวิธีรับช่วง; งานและสถานะจริงยังอยู่ในส่วนเดิมของหน้า ไม่สร้างแผนหลักซ้ำ
- [ชุดสกิลทำงาน](https://chatgpt.com/plugins/plugins_6ae6f50b063081918275e04d86a7ca0c) เป็นวิธีทำงานและสคริปต์ที่มีรุ่นกำกับ รุ่นนี้ 0.7.2 มี 9 สกิล ใช้ [ทะเบียนแบบข้อมูล](central-capabilities.json) และ [ทะเบียนหลักฐานเดิม](capability-register.md) เลือกอ่านคู่มือเฉพาะที่เกี่ยวข้อง
- ไฟล์จริงและโครงการที่แก้ต่อเก็บใน Drive ตาม ID/ลิงก์ในหน้าแผน ไม่เก็บสื่อขนาดใหญ่หรือข้อมูลบัญชีในตัวสกิล พาธ runtime อาจหมดอายุ

Notion เก็บสถานะและบทเรียนที่เปลี่ยนตามงาน; ปลั๊กอินเก็บขั้นตอนและสคริปต์ที่ตรวจเวอร์ชันได้ บทเรียนไม่ถือเป็นโค้ดที่ติดตั้งแล้วจนบันทึก release และอ่านกลับสำเร็จ

## เริ่มงานจากแชตใหม่

1. ใช้คำขอปัจจุบันของผู้ใช้ก่อน ระบุผลงานที่ต้องส่ง ไม่ถามซ้ำสิ่งที่มีอยู่
2. เปิด Notion ส่วน 7.8 แล้วอ่านเฉพาะสถานะ บรีฟ คำแก้และแหล่งไฟล์ของงานนั้น ใช้ผล fetch ล่าสุดในงานเดียวกันร่วมกัน ไม่ต้องเปิดซ้ำทุกสกิล
3. อ่านทะเบียนทักษะ เลือกสกิลตามงาน และตรวจเครื่องมือจริง เช่น Notion, Drive, runtime, FFmpeg, ASR หรือ Browser การมีคู่มือไม่ยืนยันการเชื่อมบัญชี/ติดตั้งโปรแกรม
4. ก่อนอ้างว่าเห็นไฟล์ ให้เปิด/ตรวจ ID จริง ใช้แฮช cache และสินทรัพย์ที่ยังตรงงานก่อนสร้างใหม่ เก็บชื่อคลิปภาษาไทยและรหัสเดิมถ้ามี
5. ลงมือในส่วนที่อนุญาต ไม่หยุดที่แผน หากขาดสิ่งที่ขวางงานจริง ให้ระบุส่วนนั้นและทำส่วนอิสระต่อ ไม่อ้างว่าทำเบื้องหลังหรือทำต่อเองหลังจบแชต
6. เมื่อได้ผลหรือคำแก้ที่ควรใช้ซ้ำ บันทึกเฉพาะความรู้และสถานะที่อยู่ในคำสั่งเก็บข้อมูลกลางนี้ ไม่ยกเป็นสิทธิ์เผยแพร่ ซื้อบริการ หรือลบข้อมูล ตรวจผลเขียนก่อนบอกว่าบันทึกแล้ว

## ถ้าเข้าถึงข้อมูลกลางไม่ได้

ค้นเครื่องมือ/การเชื่อมที่ตรงงานก่อนขอข้อมูลซ้ำ ใช้คู่มือและ snapshot ในปลั๊กอินเป็นจุดเริ่มโดยติดป้ายวันที่ ไม่อ้างเป็นสถานะสด หากคำตอบต้องอาศัยไฟล์/ข้อมูลที่ยังเข้าไม่ถึง ให้ถามเฉพาะส่วนที่ขาด งานเขียนหรือวิเคราะห์ที่มีข้อมูลในแชตครบทำต่อได้ การเปิดปลั๊กอินหรือ Notion ในแชตหนึ่งไม่ได้เชื่อมต่อทุกแชตอัตโนมัติ

## วิธีรักษาข้อมูลกลาง

บันทึกแต่ละบทเรียนเป็น ชื่อทักษะ | ปัญหาที่แก้ | แหล่งและวันตรวจ | ขั้นตอนที่นำมาใช้ | งานเบนที่เหมาะ | ผลทดลอง/ไฟล์/รุ่น | คำแก้เบน | ข้อจำกัด | สถานะ | ขั้นทดสอบถัดไป

ระดับที่ใช้: **คู่มือพร้อมใช้ / ทดสอบจริงรอบนี้ / มีหลักฐานบันทึกเดิม / ยังไม่ทดสอบ / พักไว้** การเปลี่ยนคู่มือไม่เพิ่มระดับเป็นทดสอบจริง ต้องมีผลจากงาน/ตัวอย่างที่ตรวจได้ ผลเดิมไม่รับรองทุก runtime

เพิ่มหรือปรับแถวเดิมตามทักษะและแหล่ง ไม่สร้างแถวซ้ำเมื่อเรียนเรื่องเดิม เก็บเหตุผลและวันที่ของคำแก้ที่เปลี่ยนวิธีทำ แยกผลลัพธ์งานจากข้อเสนอ ไม่เก็บรหัสผ่าน token cookies signed URL หรือข้อมูลส่วนตัวที่ไม่จำเป็น

อัปเดต Notion เพื่อเก็บสถานะและบทเรียน; แก้ปลั๊กอินเมื่อเป็นวิธีทำงาน/สคริปต์ที่ควรใช้ทุกงาน โดยใช้ workflow Update Plugin ที่มีสิทธิ์และตรวจ readback ไม่กล่าวว่า Notion แก้ปลั๊กอินอัตโนมัติ แชตใหม่ต้องโหลดรุ่นและอ่านแหล่งเอง

## ปรับใช้กับงานเรา

ชื่อช่อง **บ่าวเบน อยากเป็นไทบ้าน**; ไทบ้านคุณภาพเป็นชื่อเดิม เนื้อหาชีวิตจริง เล่าเหมือนคุยกับเพื่อน ใช้เสียง/เหตุการณ์จริง ไม่สร้างปัญหาหรือผลทดลองเพิ่มเพื่อให้เรื่องแรง

สายงาน: อ่านงานและบรีฟ → ตรวจฟุตเทจ/ซับ → คำถามหลักและฮุก → paper edit → ภาพพิสูจน์คำพูด → ตัดต่อภาพ/เสียง/ซับ → ตรวจตัวอย่างตามบรีฟ → ผลส่งมอบแก้ต่อได้ → วัดผลจริง

ใช้ [กระบวนการตัดต่อเล่าเรื่อง](story-driven-editing.md) และ [แม่แบบแผนตัด](story-edit-template.json) สำหรับการตัดสินใจใน timeline ไม่ยัดสูตรบ้านสามชั้นกับทุกเรื่อง คำแก้ที่ผู้ใช้ให้แล้วมีผลเหนือ snapshot เก่า หากหน้าแผนระบุอนุมัติตัวอย่างของงานนั้นแล้ว ไม่รออนุมัติซ้ำเพราะคู่มือทั่วไปพูดถึงขั้นตัวอย่าง

## ประโยคเริ่มงานข้ามแชต

“ทำงานบ่าวเบนต่อจากหน้าแผนหลัก https://app.notion.com/p/40b52d4a2f43818d8e8ccf778995100f อ่านส่วน 7.8 และสถานะงานที่เกี่ยวข้อง ใช้ชุดสกิลทำงานรุ่นล่าสุด ตรวจเครื่องมือและไฟล์จริง แล้วทำงานที่พร้อมต่อโดยไม่ถามบรีฟที่มีแล้ว”

ประโยคนี้เป็นตัวช่วย ไม่ใช่สิ่งที่ผู้ใช้ต้องคัดลอกทุกครั้ง แชตที่โหลดสกิลนี้มีลิงก์เริ่มต้นอยู่แล้ว ไม่อ้างว่าประวัติแชตเก่าหรือไฟล์แนบทุกไฟล์ตามไปอัตโนมัติ
