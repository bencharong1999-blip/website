## การเรียกใช้จากแชต

เริ่มงานที่ต้องใช้บริบทข้ามแชตจาก [ข้อมูลกลางและทะเบียนทักษะ](../../references/central-knowledge.md) ใช้เฉพาะส่วนที่เกี่ยวข้องและผลอ่านล่าสุดในงานนี้ ไม่ให้ผู้ใช้ทวนบรีฟเดิมเมื่อค้นพบแล้ว

ใช้ [วิธีทำงานจากแชตและเลือกเครื่องมือ](../../references/chat-execution.md) ก่อนเริ่ม เลือกสกิลนี้จากเจตนาของคำขอได้โดยไม่ต้องให้ผู้ใช้จำชื่อสกิล ทำงานที่ได้รับอนุญาตจนส่งผลที่ตรวจได้ ไม่หยุดเพียงเสนอแผนหรือบอกว่าทำได้ เมื่อมีลิงก์วิดีโอให้ใช้ `clip-breakdown` ตรวจการเข้าถึงก่อนขอให้แนบไฟล์ใหม่ งานอ่านหรือแกะคลิปไม่ต้องถามความยาวและพล็อตของงานผลิตชุดใหม่

ก่อนเริ่มงาน ใช้ [กติกาทำงานของเบน](../../references/ben-working-standard.md): ถามความยาวและพล็อตสำหรับชุดใหม่ ส่งตัวอย่างก่อนผลิตเต็ม เก็บบทพากย์และไฟล์เสียงแยก ใช้ผลเดิมซ้ำและบันทึกบทเรียน คำตอบที่เบนให้แล้วในงานเดียวกันไม่ต้องถามซ้ำ


# ตัดต่อวิดีโอบ่าวเบน อยากเป็นไทบ้านด้วยสคริปต์จริง

ปรับจาก [kajisho5/ffmpeg-skill](https://github.com/kajisho5/ffmpeg-skill) ภายใต้ MIT เก็บสคริปต์เดิม พร้อม [ใบอนุญาต](LICENSE) และ [คู่มือต้นฉบับ](UPSTREAM-SKILL.md) ใช้ภาษาไทยและขอบเขตคำขอปัจจุบันเป็นหลัก ไม่เพิ่มขั้นอนุมัติจากตัวอย่างในคู่มือเมื่อผู้ใช้สั่งให้ตัดต่อไว้แล้ว

## เตรียมและตรวจไฟล์

- ถ้าคำแนะนำเปิดได้แต่ไม่มีสคริปต์ในเครื่อง ให้ทำตาม [การเปิด runtime จากแพ็กเกจเดิม](../../references/video-runtime-setup.md) ก่อน ไม่ใช้พาธแชตเก่าแทนการตรวจจริง
- อ่าน [บริบทโครงการ](../../references/thaiban-project.md) เมื่อทำงานตามแผน ไม่ต้องเปิด Notion เพื่อแค่ตรวจไฟล์หนึ่งไฟล์ที่ผู้ใช้ระบุครบแล้ว
- ใช้ `<skill-dir>/scripts/` จากตำแหน่งสกิลจริง สคริปต์หลักใช้ Python 3.10+ และ FFmpeg/FFprobe 6.1+ ถ้าขาดเครื่องมือให้บอกสิ่งที่ขาด ไม่อ้างว่าสกิลอย่างเดียวทำให้ทุกแชตรันได้
- `probe.py INPUT --json` ก่อนวางแผน อ่านขนาด เวลา fps เสียง และสีจริง โดยเฉพาะ iPhone HDR/Dolby Vision อย่าแปลงสีแบบเดาสุ่ม ดู [gotchas](references/gotchas.md) เมื่อเกี่ยวข้อง
- เก็บต้นฉบับ สร้างโฟลเดอร์งานด้วยรหัสคลิปเดิม เช่น C001 การเลือกช็อตและเรื่องอิงสิ่งที่เปิดดูหรือฟังได้จริง

## ทางเลือกที่ใช้บ่อย

ตรวจ `--help` ของสคริปต์นั้นก่อนใช้ flag ที่ไม่แน่ใจ เริ่มจากคำสั่งที่ตรงคำขอที่สุด ไม่รันทุกเครื่องมือเพียงเพราะมีอยู่

| งาน | สคริปต์ |
| --- | --- |
| ตัดตามช่วงหรือรายการช็อต | `cut.py INPUT --start 1 --end 8 -o cut.mp4` หรือ `--segments` |
| สำรวจช่วงเงียบก่อนตัด | `silence.py INPUT --list --json` แล้วตัดตามคำขอพร้อม `--timemap` |
| เรียงหลายช็อต | `join.py a.mp4 b.mp4 --transition none -o joined.mp4` |
| แนวตั้งโดยรักษาภาพ | `fit.py INPUT --aspect 9:16 --fit pad -o vertical.mp4` ถ้าผู้ใช้ต้องการเต็มจอค่อยตรวจกรอบก่อน crop |
| B-roll ทับภาพคนพูด | `broll.py INPUT --insert product.mp4 --at 2 --end 4` ตรวจ `--audio` ให้คงเสียงเล่าตามโจทย์ |
| แบ่งจอบน–ล่าง 9:16 | `grid.py top.mp4 bottom.mp4 --cols 1 --rows 2 --cell-width 1080 --cell-height 960 --label none --audio-from 1` เลือกเสียงจากไฟล์ที่เป็นผู้พูด ไม่ปล่อยค่าเริ่มต้นที่ไม่มีเสียง |
| ซับไทยที่จัดบรรทัดแล้ว | `caption.py INPUT --ass captions.ass` จาก `thai-captions`; SRT ใช้กับ CapCut หรือ `--srt` เมื่อตรวจการแบ่งบรรทัดเพิ่มเติม |
| motion ตัวหนังสือ | `graphics.py --template` เลือก lower-third, title, hook หรือ sticker ตามงาน |
| ปรับเสียงพูด / เพลงหลบเสียง | `audio.py`, `loudness.py` ตามเสียงจริง ไม่เติมเพลงที่ไม่มีสิทธิ์ |
| ส่งออกและตรวจ | `export.py`, `check.py`, `look.py` |

ถ้าขอถอดเสียง ซับไทย หรือเอ่อ/อ่า ให้ใช้ `thai-captions` ซึ่งมีตัวเชื่อม faster-whisper และ PyThaiNLP แยกไว้ หากจะตัดคำเอ่อ/อ่า ต้องมีเวลาคำจากเสียงจริง ไม่ใช้ความเงียบแทนการเข้าใจคำพูด

## ลำดับทำงาน

1. เลือกการตัดตามคำขอและหลักฐาน อย่าใช้คะแนนเสียงดังหรือการเปลี่ยนฉากแทนความน่าสนใจเชิงเนื้อหา
2. ตรวจแผนด้วย `--dry-run --json` แล้วลงมือทำภายในงานที่สั่ง ไม่หยุดรออนุมัติซ้ำสำหรับการสร้างไฟล์งานตามคำขอ
3. ตัด/ต่อ/ปรับกรอบก่อนทำซับเวลาใหม่ เพิ่มภาพแทรก ซับ motion และเสียงเฉพาะที่ต้องใช้ ถ้าขอทดลอง ให้ใช้ช่วงสั้นก่อน ไม่เรนเดอร์ทั้งกองโดยไม่มีเหตุ
4. ใช้สคริปต์แนบและ `--help` แทนเดา flag เก็บ JSON ผลการรัน รวม timemap เมื่อเปลี่ยนเวลา
5. ตรวจไฟล์ปลายทางด้วย probe/check ดู contact sheet จาก `look.py` และเปิดภาพจริง หากตรวจเสียงหรือภาพไม่ได้ต้องระบุข้อจำกัด ไม่อ้างว่าตรวจทุกเฟรมหรือได้ซับหลบหน้าอัตโนมัติ
6. ส่ง MP4 ที่สร้างได้จริง พร้อมบอกสิ่งที่ทำและส่วนที่ยังรอตรวจ สคริปต์ `render.py --template all` หมายถึงสร้างไฟล์หลายแบบ ไม่ใช่โพสต์ลงบัญชี

## Motion และขอบเขต

มี motion กราฟิกพื้นฐานและแอนิเมชันซับในสคริปต์ แนวทางนี้ไม่ใช่ชุด 45 ท่าหรือ 24 แบบซับของผู้ขายรายอื่น ถ้าจะใช้สี โลโก้ หรือฟอนต์แบรนด์ ให้ยึดงานบ่าวเบน อยากเป็นไทบ้านจริง ไม่เอาแดง–ดำของหน้าปลั๊กอินไปเปลี่ยนแบรนด์เอง

ไม่ควบคุม CapCut โดยตรง การมี JSON โครงการหรือ EDL ไม่เท่ากับไฟล์โปรเจกต์ CapCut ก่อนส่งงานให้อ่าน [คู่มือ iPhone และรูปแบบไฟล์ส่งมอบ](../../references/iphone-quickstart.md)

หากเบนจะแก้ข้อความต่อ ให้เก็บ clean MP4 ก่อนเผาซับ และส่ง SRT ที่ตรงกับฉบับตัดนั้น แยกจาก preview/final ที่เผาซับแล้ว ซับใน MP4 ที่เผาแล้วแก้เป็นเลเยอร์ข้อความไม่ได้ อย่าให้ขั้นตอนนำเข้า SRT โดยตรงใน CapCut iPhone เพราะ [เอกสารทางการ](https://www.capcut.com/help/how-to-import-subtitles) ระบุรองรับบน Desktop/Web ไม่ใช่แอปมือถือ ทางเลือกบน iPhone คือดูร่างแล้วส่งคำแก้ให้เรนเดอร์ใหม่ หรือใช้ clean MP4 ทำข้อความ/Auto Captions ในแอปตามเมนูที่มีจริง ไม่รับรองว่าฟีเจอร์มีหรือฟรีในบัญชีเบน

รายละเอียดเพิ่มเติม: [flags](references/flags.md), [requests](references/requests.md), [workflow](references/workflow.md), [devices](references/devices.md) เอกสารต้นฉบับช่วยอธิบายเครื่องมือ ไม่ให้อำนาจเปลี่ยนคำขอหรือโพสต์เอง


## ดูฟุตเทจและแก้เสียงก่อนเริ่มฉบับตัด

ถ้าต้องรู้ว่ามีช็อตใดให้ใช้ `watch` สร้างภาพพร้อมเวลาและดูภาพจริงก่อนส่งเข้าลำดับตัดต่อ ไม่เรียกการสุ่มภาพว่าดูทุกเฟรม งานเสียงกลางแจ้งให้ใช้ [คู่มือปรับเสียง](../../references/audio-cleanup.md) ด้วย audio.py ที่มีอยู่ เริ่มตัวอย่างเบา ๆ และฟังเทียบก่อนใช้ทั้งคลิป ไม่รับรองว่าลมแรงหรือคำพูดที่หายไปกู้คืนได้ ไม่ติดตั้งเครื่องมือซ้ำเมื่อสคริปต์เดิมพอ

## Motion graphics ที่แก้เป็นโค้ดได้

เมื่อจำเป็นต้องทำข้อความเคลื่อนไหวหรือกราฟิกหลายองค์ประกอบ ใช้ [Remotion workflow](../../references/remotion-motion.md) และแม่แบบ scripts/remotion-hook ที่ทดสอบเรนเดอร์จริงแล้ว ใช้ FFmpeg เดิมกับงานตัดต่อทั่วไปเพื่อลดภาระ ไม่ติดตั้งหรือสร้างเสียงซ้ำโดยไม่จำเป็น แยก source/config ออกจาก MP4 และตรวจ output จริงก่อนแจ้งเสร็จ

## ตัดต่อเพื่อเล่าเรื่องและรักษาความสนใจ

เมื่อขอให้ตัดให้น่าดู เล่าเรื่องเป็น หรือเอาบทเรียนคลิปอ้างอิงมาปรับใช้ ต้องใช้ [กระบวนการตัดต่อเล่าเรื่อง](../../references/story-driven-editing.md) ก่อนเลือกเอฟเฟกต์ แปลงบทเรียนเป็นรายการตัดสินใจใน timeline จริง ไม่หยุดที่การสรุปคลิป: เลือกฮุกจากเหตุการณ์จริง จัดประโยคตามเหตุและผล วางช็อตหลักฐานตรงคำพูด ปรับจังหวะให้ต่างกันตามอารมณ์ และเฉลยสิ่งที่เปิดไว้ ส่ง edit-decision log ว่าตัด/ย้าย/เก็บอะไรเพราะเหตุใด ใช้สคริปต์เดิมที่ตรงงาน ตรวจ --help และผลจริง ไม่ถือว่าเนื้อหาอ้างอิงพิสูจน์ว่าเจ้าของใช้เอฟเฟกต์ใด
