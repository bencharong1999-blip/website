## การเรียกใช้จากแชต

เริ่มงานที่ต้องใช้บริบทข้ามแชตจาก [ข้อมูลกลางและทะเบียนทักษะ](../../references/central-knowledge.md) ใช้เฉพาะส่วนที่เกี่ยวข้องและผลอ่านล่าสุดในงานนี้ ไม่ให้ผู้ใช้ทวนบรีฟเดิมเมื่อค้นพบแล้ว

# แกะคลิปจากหลักฐานและนำไปใช้

ใช้ [วิธีทำงานจากแชต](../../references/chat-execution.md) ไม่ต้องให้ผู้ใช้ย้ำชื่อสกิล ทำงานต่อในขอบเขตที่อนุญาตจนส่งผลที่มีหลักฐาน ก่อนถามให้ส่งไฟล์ใหม่ ตรวจเครื่องมือที่มีและช่องทางสาธารณะที่เหมาะสมก่อน

## เข้าถึงและระบุคลิป

1. เก็บ URL เดิมและ canonical URL ระบุว่าอันไหนต้นฉบับ/คลิปวิเคราะห์ตามที่ผู้ใช้บอก อย่าสรุปว่าเป็นคลิปตัดย่อเพียงเพราะส่งมาคู่กัน
2. ค้น connector/API ที่เกี่ยวข้องก่อนใช้ Browser ถ้าต้องใช้ Browser อ่านสกิล Browser และตรวจว่ามีเครื่องมือจริง คู่มืออย่างเดียวไม่เท่ากับการเชื่อมต่อ
3. ถ้ามี runtime และสิทธิ์เครือข่าย ใช้คำขอเว็บสาธารณะปกติผ่าน proxy/CA ที่กำหนดได้ อ่านสกิล runtime เมื่อเกี่ยวข้อง ใช้ `scripts/inspect_public_tiktok.py URL --out-dir PATH` สำหรับ TikTok สคริปต์ใช้ Python stdlib ไม่ต้องติดตั้ง requests และไม่ได้เล่นหรือดาวน์โหลดวิดีโอ
4. สคริปต์แก้ short link อ่าน metadata, ซับไทย และภาพปกจากข้อมูลหน้าเว็บสาธารณะ ถ้าไม่มีข้อมูลที่คาดไว้ให้รายงานขาดตามจริง ไม่ให้ผู้ใช้วาง cookies/token ไม่ข้าม login, CAPTCHA, paywall หรือ HTTP 403 ของสื่อ
5. หากมีวิดีโอที่เปิดได้จริง ส่ง `watch` ตรวจภาพและ `thai-captions` เมื่อจำเป็นต้องถอดเสียง ใช้ซับแพลตฟอร์มที่มีอยู่ก่อนเพื่อประหยัดงาน แต่ระบุว่าเป็น ASR และตรวจคำสำคัญเมื่อมีเสียง
6. ถ้าเครื่องมือเดิมยังขาดความสามารถ ค้นปลั๊กอินที่ตรงงานและตรวจสถานะเชื่อมต่อจริง ใช้เฉพาะเมื่อพร้อม ไม่รับรองว่าจะเล่น TikTok ได้จากคำอธิบายปลั๊กอิน

## ระดับหลักฐาน

- metadata/คำบรรยาย: ยืนยันชื่อผู้โพสต์ ระยะเวลา และสิ่งที่ข้อความระบุ ไม่ยืนยันเหตุการณ์ในวิดีโอ
- ซับแพลตฟอร์ม: วิเคราะห์คำพูดและลำดับเรื่องได้โดยระบุ ASR; ไม่ยืนยันน้ำเสียง เพลง เอฟเฟกต์ หรือเวลาตัดละเอียด
- ภาพปก: บอกได้เฉพาะภาพนั้น ไม่ยืนยันภาพทั้งคลิปหรือยอดปัจจุบันจากตัวเลขที่พิมพ์ไว้
- เฟรมตามเวลา: ระบุจำนวนและช่วงที่ตรวจ ไม่อ้างทุกเฟรม
- เสียง/วิดีโอจริง: รายงานเฉพาะช่วงที่ได้ฟัง/ดู ไม่อ้างชมครบจาก probe หรือการถอดรหัสไฟล์

## แกะเรื่องและเทียบ

ระบุฮุก เป้าหมาย เดิมพัน อุปสรรค การตัดสินใจ เหตุผล ผลลัพธ์ และการปิดเรื่อง ทำตารางเวลาโดยประมาณ | เนื้อหาจากหลักฐาน | หน้าที่ในเรื่อง | สิ่งที่นำไปใช้ แยกความเห็นผู้วิเคราะห์จากข้อสังเกตของเรา หากหลักฐานพอ ให้ส่งผลวิเคราะห์ทันทีพร้อมข้อจำกัด ไม่หยุดแค่บอกว่าเปิดวิดีโอไม่ได้

อ่าน [กรณีบ้านสามชั้นและบทเรียน](../../references/clip-storytelling-case.md) เมื่อต้องใช้ตัวอย่าง stakes/why/จุดเปลี่ยน อย่าคัดลอกเรื่องหรือคำกล่าวอ้างมาเป็นประสบการณ์ของผู้ใช้ ไม่รับรองว่าสูตรใดทำให้ไวรัลโดยไม่มีข้อมูลผลทดลอง

## ส่งมอบ

ส่งข้อค้นพบหลักก่อน ตามด้วยโครงเรื่องมีเวลา แยกสิ่งที่ตรวจแล้วและยังขาดสั้น ๆ ปิดด้วยโครงที่นำไปใช้กับเรื่องจริงได้ หากขอเขียนต่อใช้ `write-and-revise`; หากขอตัดต่อจริงใช้ `ffmpeg-skill` และต้องมีไฟล์ที่เปิดได้ เก็บลิงก์และบทเรียนที่ผู้ใช้อนุญาต แต่ไม่ใส่ signed URL หรือข้อมูลบัญชีลงแพ็กเกจ

## เมื่อผู้ใช้ต้องการเพิ่มฝีมือให้เอาไปทำงานเรา

คำขอ “เรียนรู้”, “เพิ่มทักษะตัดต่อ”, “เอามาปรับใช้กับงานเรา” ต้องแปลงบทเรียนเป็นวิธีเลือกเรื่อง คัดช็อต วาง timeline และตรวจฉบับตัด ตาม [กระบวนการตัดต่อเล่าเรื่อง](../../references/story-driven-editing.md) การสร้างสกิลเปิดลิงก์อย่างเดียวไม่ตอบเป้าหมายนี้ แยกหลักที่ได้จากแหล่งอ้างอิงออกจากเทคนิคที่เราเสนอเพิ่ม ใช้ write-and-revise/watch/ffmpeg-skill/quality-check ทำงานต่อเมื่อมีไฟล์และบรีฟพร้อม ไม่อ้างว่าเก่งกว่าต้นทางหรือทำคลิปจริงเสร็จจากการแก้คำแนะนำ
